# 节奏：WIP、日巡、周收口、复盘

> 管理 bot 的价值不在「知道所有事」，在**按固定节奏问对几个问题**。节奏丢了，台账就变成一堆没人看的文件。

## WIP 上限：在途单 ≤ 3

**为什么是 3**：并行度不是越高越好。四条以上在途，本质上等于没有一条能按时交，而且每条都停在「半成品」这个最危险的中间态。

**超限时怎么办**：不派新单，先收口。收口优先于开工。

**例外**：明确标注为「等外部、不占本轮产能」的 BLOCKED 单不计入 WIP。这也是为什么 `blocked_by` 必填——它决定这条算不算在途。

## 每轮开工四问（30 秒）

| # | 问题 | 数据来源 | 答不出来说明 |
|---|---|---|---|
| 1 | 谁空闲？ | 团队花名册 + QUEUE owner | 你不知道谁在干什么 |
| 2 | 在途几条？ | QUEUE 的 RUN 计数 | 台账过期了 |
| 3 | 下一步是什么？ | 判定链 + 上游产物尾部 | 你在按「最近谁在问」排优先级 |
| 4 | 有没有门挂着？ | `evidence/` 最新日志 | 有工序正在被一个门无谓地卡住 |

**第 3 问的口径**：下一步来自判定链，不来自最近的消息。消息只影响 urgency，不影响 sequence。

## 每日巡检（15 分钟，不等回执）

1. **mtime 对派发时间**：产物最后修改时间晚于派发时间，才算真在跑。台账写 RUN 而 mtime 没动的，去问
2. **逾期单**：超 `due` 未交 → 重排基线或升级。**不许静默延期**——连续两次漂移要升级
3. **WIP 计数**：超限即停派
4. **未受控变更**：盘上文件 sha 变了但 MANIFEST 无行 → 按事故处理，追写入方

## 每周收口（一页）

**三项**：
- 本周交付（每条带 sha）
- 在途与风险（含风险登记更新）
- 要拍板的事

**四指标**：
| 指标 | 算法 | 用来看什么 |
|---|---|---|
| 按期率 | 按期完成 / 本周应完成 | 排期是否可信 |
| 一次验收通过率 | 首轮过 / 总收口 | 派工质量与验收清晰度 |
| 机制债 | 欠了几条「该写没写」的规则 | 积累性风险，最容易被忽略 |
| 知识/资产状态 | 新增/更新的产物数 | 是在产出还是在返工 |

**上一期问题闭环**：逐条写「已闭环 / 未闭环 + 卡在哪」。这一节不能省，否则周报会变成每周重复同一份问题清单。

## 每役复盘（一页）

- **Top3 根因**（不是 Top3 现象）。现象是「文件名写错」，根因是「派工单不强制写绝对路径」
- **机制改动**：改规则，不是改人。写「下次要注意」等于没改
- **下役实验项 1 条**：只做一条，做多了没有一条能验证

## 六红旗（见到就报，不用请示）

| 红旗 | 判据 | 处置 |
|---|---|---|
| 范围蔓延 | 派工单任务在执行中变大且无变更单 | 停工，出变更单 |
| 期限漂移 | 逾期且基线未重排 | 重排并留痕，连续两次升级 |
| WIP 超限 | 在途 > 上限 | 停派新单，先收口 |
| 未受控变更 | 文件 sha 变了但台账无行 | 按事故处理，追写入方 |
| 风险爆冷 | 出了问题但风险登记里没有 | 记一条「漏登记」，补进登记 |
| 验收造假 | 报「通过」但盘上无产物／无 exit code | 按最严重级记，重验 |

## 「等」的三件套

说「等」必须同时说清：

1. 在等什么（具体到哪个人、哪份产物）
2. 等的时候在做什么（把不依赖它的工序列出并派出）
3. 什么时候重判（具体时点，不是「回头看看」）

只说「等 X」的消息，一律视为本轮的活没干完。

## ✗ 常见错法

✗ 四个载体一次建齐。结果四个都没人写，还让人误以为有台账——建了不用比没建更糟。
