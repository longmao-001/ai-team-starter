# 03 团队作业台（纪律与流程）

> 团队开始**并行**干活时才需要它：三个人同时动手，就必须有派工单、验收串、门控、台账、备份。
> 本目录正文由项目经理负责填写；结构沿用仓库占位壳，**五节顺序固定**。

## 五节：本目录怎么覆盖

| 节 | 内容 | 判据 | 落在哪个文件 |
|---|---|---|---|
| 1 派工单 | 任务 ID、输入、输出、验收、截止 | 拿单能开工 | `02-dispatch-and-acceptance.md` |
| 2 验收串 | 机器可核判据 | 能 grep / 能数 / 能对账 | `02-dispatch-and-acceptance.md` |
| 3 门控 | 哪些门、跑哪个脚本、不过怎么办 | 只跑现成脚本，不改阈值 | `03-gates.md` |
| 4 台账 | 在途、已收、清僵尸行 | 状态汇报必须核实际状态 | `04-ledgers.md` |
| 5 备份与恢复 | 备份什么、怎么验、怎么回 | 没演练过的备份不算备份 | `05-backup-rollback.md` |

## 通用纪律（可直接抄的六条）

1. 报数带四件套：数字、口径、范围、快照时点/哈希
2. 负结论要回显依据：查了什么、0 命中对应哪个节点
3. 写域边界：不写别人的目录；要改共享文件先出变更单
4. 三件套：备份、干跑、回滚路径，缺一不动手
5. 不编造：缺数据写「缺」
6. 状态断言前先核实际状态，不照台账念

八条完整版在 `01-discipline.md`，多出两条：哈希与行数的口径细则、写域越界后的处理。

## 四个载体（每个解决一件事，别新造第五个）

| 载体 | 解决什么 | 什么时候写 |
|---|---|---|
| `QUEUE.md` | 谁在干什么、卡在哪 | 派工即写，状态变化当日改 |
| `MANIFEST.md` | 交过什么、谁交的、sha 多少 | 每次收口追加一行 |
| `PROVENANCE.md` | 盘上现在的东西从哪来 | 每轮开工核对 |
| 派工单目录 | 每张单的五要素原文 | 派工前 |

最小可用版本：只要一个 `QUEUE.md`。其余三个在第一次「换人接手」或「文件被改坏」之后，你会自己想加。

## 一套节奏

| 周期 | 动作 | 产物 |
|---|---|---|
| 每轮开工 | 四问：谁空闲 / 在途几条 / 下一步 / 有没有门挂着 | `STAGE:` 一行 |
| 每日 | 巡检 15 分钟：mtime、逾期、WIP、未受控变更 | QUEUE 状态修正 |
| 每周 | 收口一页：三项 + 四指标 | 周报 |
| 每役 | 复盘：Top3 根因 + 机制改动 | 复盘条目 |

节奏比载体重要。四个载体都建了但没人按节奏写，等于四个空文件夹。

## 常见写歪

- 纪律写成口号（「注意质量」「及时沟通」），无法判生死
- 台账人工维护，三天后全是过期行
- 备份只做不验，恢复时才发现不可用
- 四个载体一次建齐，结果四个都没人写

✗ 常见错法：把「纪律」抄进每个 bot 的 instructions。纪律只有一处正文（本目录），其他位置只留指针——复制粘贴的规则不是备份，是分岔起点。
