# 发布流程

目标：**公开的仓库里不能有一条私人信息，且发布动作可回退。**

## 1. 版本号与 tag

- 版本号放 `VERSION`（一行，如 `0.1.0`），变更写 `CHANGELOG.md`。
- tag 形如 `v0.1.0`，**指向一个提交，不指向分支**。
- 0.x 阶段允许不兼容改动；1.0 之后再谈兼容承诺。

```bash
# 打 tag（annotated，不是 lightweight——lightweight 没有作者与时间，事后无法追责）
git tag -a v0.1.0 -m "v0.1.0 骨架首版：三类角色模板 + 脱敏扫描 + 发布流程"
git push origin v0.1.0
```

## 2. 发布前四道门（按顺序，缺一不推）

### 门 0：历史扫描（不是工作区扫描）
工作区干净 ≠ 仓库干净。一次"先 push、后扫出命中、再修工作区"，修的是**最新那一版**；旧版本还在历史里，`git clone` 就能翻到。

```bash
# 逐提交扫（同一套规则表，不另抄一套）
python 90-tooling/scan_history.py --denylist 90-tooling/rules/denylist.local.txt
```

- 有 BLOCK 不等于必改写历史：**每条命中必须定性**——泄露（真实人名/机构/可用路径/凭据）清历史；无害形态（示意用省略号、规则文档里的示例写法）记录结论即可。
- 定性结论写进 CHANGELOG；已定性的登记到 `90-tooling/rules/history-waivers.txt`（提交短sha|文件|规则|理由），扫描时单独列出、**不算通过但可审计**，不会静默消失。
- 判据：真实人名 / 机构名 / 可用路径 / 凭据 → 一律清历史，**不许豁免**；示意用省略号、规则文档里的示例写法、无个人信息的路径形态 → 可豁免。

### 门 1：脱敏扫描 PASS

```bash
# 本地跑，带实体名单（发布门必须带；CI 只能跑结构层）
python 90-tooling/sanitize_scan.py --root . --require-denylist --report scan-report.md
```

- 要求：`BLOCK = 0`。
- WARN 逐条给理由，写进回执。
- `--require-denylist` 的作用：名单文件不在就直接报错，避免"以为扫了其实只扫了半层"。

### 覆盖数：门必须报告「实际扫了多少」

任何门都要报两行：**扫了多少个文件 / 多少字节**。**`0 个文件` 一律判 FAIL，不许报 PASS。**

为什么：`git archive | tar -x` 在 PowerShell 里会把二进制流弄坏，导出 0 个文件，而扫描器对空目录报「0 命中」——看起来完全通过。**空结果不是干净，是假门。**

同类漏扫还有两处，都是实案：
- 扩展名不在白名单的文件会被**静默跳过**（`.template`、`.jsonl` 曾整类漏掉 3 件）；
- URL 里 `https://` 这一串曾被盘符正则误判（把 scheme 后面的斜杠当成盘符分隔），规则已排除——否则全仓库的 URL 都进 WARN，真命中会被淹在误报里。

### 门 2：体积与文件类型

```bash
# 单文件 > 5 MB 一律不入库（扫描器已按 5 MB 报 BLOCK）
python 90-tooling/sanitize_scan.py --root . --block-mb 5
```

还要人眼过一遍：`runs/`、`tmp/`、`*.log`、二进制、模型权重、数据集、压缩包——**产物不入库**，这是纪律不是建议。

### 门 3：编码与换行

- 全部 UTF-8 无 BOM、LF。
- `.gitattributes` 里 `* text=auto eol=lf` 已强制；但**已有文件不会自动回改**，扫描器会把含 CRLF / BOM 的文件列出来。

### 门 4：内容自检

- 每节结尾有「常见写歪」吗？
- 有没有"一般来说""通常情况下"这类不可核的句子？
- 示例里的占位符是否只有约定那三个（多一个就多一条扫描规则，容易漏）？

## 3. 先私有、后公开（最重要的顺序）

**新建仓库一律先 private，推上去、核干净，再改 public。**

```bash
# 推之前设默认私有的理由：一旦 public，任何被推送过的历史都会被镜像、被缓存，
# 就算随后删除，也删不干净。
```

流程：

1. 建 private 仓库
2. 推上去（`GIT_TERMINAL_PROMPT=0`，让它快速失败而不是挂在等凭据上）
3. **从远端侧核**：分支列表出现该 sha、随机取一个文件能看到内容——本地 exit 0 不算证明
4. 过完四道门后，才在仓库设置里切成 public
5. 切公开后，再核一次"没有 private 分支、没有多余 tag"

## 4. 推送纪律

### 与他人在途编辑共存时：禁用 `reset --hard` / `checkout --`

多人往同一个仓库写的时候，工作区里躺着的**未提交内容不属于你**，但它一样会被下面两条命令抹掉：

```bash
git reset --hard <ref>          # 未 add 的修改直接消失
git checkout -- <path>          # 同上
```

实测后果：作者改好一页、还没 `git add`，一条 `reset --hard` 之后**既不在历史里，也不在 reflog、也不在 `git fsck` 的悬空对象里**——未 add 的内容从不进对象库，找不回来。

规矩：动手前先 `git status`，看到 `M` 的路径不是你的就别碰；需要以远端为基线时用 `git stash push -u` 或 `git add -N` 先保住现场，合并完再 `git stash pop`。


### 改写历史（force-push）的三条硬规矩

发布过之后再 force-push，问题不在正文里，**正文扫描永远扫不出来**：

0. **改写已发布历史要有人批**：历史层出现 BLOCK 时，**先停下报负责人**，由负责人决定「豁免 / 改写 / 收库」。执行的人不得单方面改写已发布历史——手里有这个权限，早晚会用在真数据上。
1. **必须记账一行**：谁、为什么、旧 sha → 新 sha、影响面。记在 [`rules/history-rewrites.md`](rules/history-rewrites.md)，只留在聊天记录里等于没有。
2. **必须验两个关系**：旧 tag 是否仍是 HEAD 的祖先（`git merge-base --is-ancestor`）；有没有只被 tag 可达、main 里没有的提交（那会造出"tag 拉得到、main 里没有"的悬空版本）。
3. **必须知道它删不掉内容**：实测——force-push 之后按旧 sha 仍能从 GitHub API 取到那个提交（返回 200），因为改写只移动引用、不删对象。**所以真实敏感信息不能靠 force-push 处置**，要走仓库删除重建或平台流程；force-push 只能用于"我们自己刚写进去、且不敏感"的内容。


```bash
export GIT_TERMINAL_PROMPT=0     # 凭据过期时快速失败，不挂住
git push origin main
git ls-remote origin main        # 远端侧核对：回来的 sha 应等于本地 HEAD
```

- **push 通 ≠ 该推**：能推是能力，推什么是判断。
- 推送后必须**远端侧核一次**（`ls-remote` 或网页看提交），本地回显 exit 0 不算证据。
- 大文件、密钥、产物一律不入库；宁可在仓库外备份，也不进 git 历史。

## 5. 回执要写清的四项

1. **commit sha**：40 位 git sha（不是 sha256，两者长度和含义都不同，别混）
2. **目录树**：`git ls-tree -r --name-only HEAD`
3. **扫描结论**：跑了哪几层（结构层 / 实体层 / 历史层）、名单几条、BLOCK / WARN 数
4. **远端证据**：`ls-remote` 输出，或分支列表里能看到该 sha

### 数字一律脚本出，禁手抄

件数、字节、占位符次数、行数——**全部由脚本现算**，且回执里带 `git rev-parse HEAD` 的**现取值**，不许引用记忆里的 HEAD。

反面记录（同一个包里真实发生过）：件数 22→25、22→21、占位符 0/1/2→2/2/3，以及按过期 HEAD 报账三次。手抄的数一律不进门。

## 6. 回滚

| 出事 | 动作 |
|---|---|
| 推送后发现敏感内容 | **立刻**改回 private → 用 `git filter-repo` 清历史 → 强推 → 核远端 → 再评估是否公开 |
| 只是漏了文件 | 追加一个提交（历史里保留，便于审计） |
| 打错 tag | 删远端 tag（`git push origin :refs/tags/vX`）后重打，并回执写明旧 sha |

> 删除提交 ≠ 删除历史。公开过的内容按"已泄露"处理。

## 常见写歪

- 先 public 再补脱敏 → 历史已被抓走，删不干净
- 只跑 CI（结构层）就宣布"扫过了" → 实体类从未检查
- 回执只给本地 exit 0，没有远端侧证据 → 无法排除"推到了别处"
