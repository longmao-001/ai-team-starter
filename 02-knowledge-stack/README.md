# 02 · 知识库 / 知识图谱 / RAG 搭建模板

> 适用领域：任意。示例用「迷你书目」——因为它没有事实性风险，又一眼能看懂多跳。
> **你要改的只有 SEED 和 Schema；流水线、门控、记账一条都不改。**

## 这套模板解决什么问题

大多数"给 AI 建知识库"的努力死在同一个地方：**存进去了，但查不准、查不到、查过之后不知道查过**。
本章的目标不是"知识多"，而是让**一条知识**走完四步：

1. 能按格式写进去（SEED 有硬约束，写错在构建期就报错）
2. 能被查出来（按名、按别名、按 ID、按多跳）
3. 能说清出处（每条边带 `source` + `source_date`）
4. 每次查询都留账（含零命中——零命中就是**该补的知识缺口**）

做到这四步，规模从 17 条涨到 17 万条只是重复劳动，不需要换架构。

## 最小可用路径（一台空电脑，约 30–60 分钟）

| 步 | 做什么 | 产物 | 通过判据（不满足就别往下走） |
|---|---|---|---|
| 0 | 装 Python 3.10+，复制 `sample/` | 一个文件夹 | `python -X utf8 --version` 有输出 |
| 1 | 填 SEED：两类 CSV | `seed/nodes.csv`、`seed/edges.csv` | 每行都有出处和日期，无空 id |
| 2 | 定 Schema | `schema.json` | id 有格式门；关系有端点约束 |
| 3 | 跑构建 | `output/kg.json` + `kg.json.sha256` | 同一输入重跑，sha 不变 |
| 4 | 建索引 | `output/kb.sqlite` | 实体数/边数与 KG 完全相等 |
| 5 | 查第一条 | JSON 结果 | 命中且能反查出处日期 |
| 6 | 记账 | `query_log.jsonl` | 四字段齐全；零命中也有记录 |
| 7 | 发布 | 预注册 + 干跑 + 回滚点 | 五项计数全对、sha 相等（见 `03-publish-discipline.md`） |

每一步的做法、命令、期望输出和失败处理：**`01-minimal-path.md`**。

## 三条硬边界（先接受，再动手）

1. **KG ≠ KB**。KG（JSON）管"实体 + 关系"，负责导航和多跳；KB（SQLite）管"属性 + 全文"，负责详情和检索。两者混在一起，改一次结构就要重建全部数据。
2. **生成器唯一写，产物带 sha**。`kg.json` 只许 `kb_build.py` 写，旁边永远有一个 `.sha256` sidecar。任何人手改一次 JSON，下一个人的"差异"就全是噪音。
3. **每次查询都记账，零命中也是账**。没有账，"这个知识库覆盖得怎么样"就只能靠感觉；有账，缺口是能数出来的。

## 先证明这套模板是活的

```bash
cd sample
python -X utf8 run_demo.py
```

期望：13 项全 PASS，最后一行 `VERDICT PASS 13/13`，并打印一个快照 sha。
它会依次验证：构建 → 同输入重跑字节全等 → 建库 → 五项体检 → 四种查询 → 零命中记账 → RAG 上下文装配。
任何一项 FAIL，脚本退出码为 1——可以直接挂进 CI，或者挂进"发布前必跑"。

**控制台要求：无。** 6 个脚本已把自身输出固定为 UTF-8（`sys.stdout.reconfigure`），Windows 默认 cp936 也不会崩；步骤标签用 `[01]` 这类 ASCII 形式，不依赖字体。若显示中文乱码，先 `chcp 65001`（见 `05-pitfalls.md` 坑 15）。

## 本模板明确不做什么

- **不裁决知识对错**。这里管"怎么写、怎么发、怎么回滚"；"这条对不对"要领域专家签字，模板只负责把出处钉在边上。
- **不默认上向量库**。先让结构化检索查得准（实体身份 + 关系 + 出处），再加向量做模糊召回。顺序反了，你会得到一个"能聊但说不清来源"的系统。
- **不做大规模爬取**。扩增留了挂点（见 `01-minimal-path.md` 末节），但每加一批都要过一次预注册 + 干跑，不允许"先跑完再补记录"。
