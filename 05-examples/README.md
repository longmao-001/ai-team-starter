# 05 脱敏实例

同一个模板，换三个行业。**看实例要看的不是内容，是"哪里换了、哪里没换"。**

| 实例 | 行业 | 状态 | 负责 |
|---|---|---|---|
| [科研课题组（脱敏）](case-research-lab.md) | 合成生物 / 科研 | 待填 | 待定 |
| [短剧项目（脱敏）](case-short-drama.md) | 影视 | 待填 | 制片人 |
| [育种平台（脱敏）](case-breeding.md) | 农业科技 | 待填 | 待定 |

## 实例写作的硬规矩

1. **三个占位符，不许自创第四个**：`某短剧项目（脱敏）`、`X万`、`{{RUN_PATH}}`。多一个占位符，扫描器就多一条规则，容易漏。
2. **凡盘符路径一律进 `{{RUN_PATH}}`**：任何"盘符 + 路径"的写法都不行，别只清某一条（真实例子里常见的是工作盘与家目录两种）。<!-- sanitize:allow -->
3. **稿尾必须附「占位符对照表」**：占位符 → 替换了哪类信息 → 出现几次。扫描器按它对账，能查出漏替换。
4. **保留结构、去掉身份**：角色名、金额、路径都替换，但流程（判型→派工→门控→台账）不许改。

## 每个实例必须包含的四段

1. **判型**：这个任务属于哪一类，为什么
2. **派工五要素**：输入、输出、验收、时限、升级
3. **门控**：跑了什么检查，不过怎么办
4. **台账**：这一轮结束时，在途表长什么样

## 常见写歪

- 写成"我们做得多好" → 读者学不到动作
- 换掉了人名却没换路径 → 一次扫描就露
- 三个实例各写一套术语 → 读者以为是三种方法
