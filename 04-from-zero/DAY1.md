# Day 1：从空电脑到三个 bot 能对话

时间盒：**6 小时**。做完打勾，没勾的不要进入下一步。

## 0. 准备（30 min）

- [ ] 定下**一个真实任务**，写进 `SCOPE.md`（一句话：输入 → 输出 → 验收人）
- [ ] 定下**数据落点**：一个工作目录，所有产出只往这里写
- [ ] 定下**不许外发的东西**：凭据、未公开数据、他人隐私

**做完的标志**：`SCOPE.md` 存在，且有验收人姓名/角色，不是"团队"。

## 1. 环境（60 min）

- [ ] 装好运行环境（模型客户端 / Agent 平台 / Python 或 Node）
- [ ] 跑通一次"hello world"级别的任务（例如读一个文件、输出一句话）
- [ ] 记下**版本号**与**装在哪**（出问题时第一个要看的东西）

**做完的标志**：一条命令能跑通并输出结果，你把命令和输出版本号记进了 `ENV.md`。

> 常见坑：Windows 上 `.ps1` 脚本存成无 BOM 的 UTF-8，中文会乱码导致引号失配、脚本静默不执行。要么只用 ASCII，要么存成 UTF-8 with BOM。

## 2. 三个角色（120 min）

按 `01-role-templates/` 建三个（不要多）：

- [ ] 一个**管理 bot**：只会话、不干活，负责拆任务
- [ ] 一个**功能 agent**：接固定输入，产出可验收的东西
- [ ] 一个**专家 bot**：只给判断与方向

**做完的标志**：三份角色卡填完，每份都能回答"它下一步会做什么"。

## 3. 第一次真实任务（120 min）

- [ ] 管理 bot 拆任务，输出**派工单**（任务 ID、输入、输出、验收、截止）
- [ ] 功能 agent 接单，产出交付物
- [ ] 专家 bot 只做一件事：**指出这份交付里最该被质疑的三处**
- [ ] 验收人按验收串判定，不通过就只改判据指出的那一处

**做完的标志**：交付物落盘、验收结论落盘（通过/不通过 + 依据），产出里带着**口径四件套**。

## 4. 收尾（30 min）

- [ ] 写 `DAY1-NOTES.md`：今天卡在哪、改了什么、明天先做什么
- [ ] 把"跑崩过的点"回写成角色卡里的**新边界条款**（一条即可）

**做完的标志**：角色卡里的边界比昨天多至少一条。**没有变长的角色卡说明你没真跑。**

## 常见写歪

- 跳过第 3 步直接建制度 → 第二天就空转
- 三个角色都写成"全能助手" → 谁都能干，等于谁都不干
- 不写 `DAY1-NOTES.md` → 第二天从零回忆
