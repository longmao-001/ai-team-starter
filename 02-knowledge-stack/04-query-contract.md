# 04 · 查询契约：记账、快照绑定与 RAG 装配

知识库只有在"被查过、且查过这件事有记录"之后才算存在。这一页定三件事：查完记什么、结论怎么绑版本、上下文怎么拼。

---

## 一、每次查询必须记的五个字段

| 字段 | 例 | 作用 |
|---|---|---|
| `query` | `山谷` | 检索式原文。**中文必须原样**，不许转成 `\u5c71` |
| `graph` | `demo-books` | 哪张图。多图并存时这是防混算的标签 |
| `snapshot_sha` | `050d0a72…` | 哪一版。同一句话在两个版本里可能是两个答案 |
| `hits` | `1` | 命中数。**0 也要记** |
| `ts` | `2026-11-11T11:37:03Z` | UTC 时间。本地时区会让跨机器对齐出错 |

可选补充：`mode`（text/id/rag）、`engine`（like/fts/graph）、`caller`（哪个 Bot / 哪条流水线）。

```jsonl
{"engine":"like","graph":"demo-books","hits":1,"mode":"text","query":"山谷","snapshot_sha":"050d…","ts":"2026-11-11T11:37:03Z"}
{"engine":"like","graph":"demo-books","hits":0,"mode":"text","query":"量子引力","snapshot_sha":"050d…","ts":"2026-11-11T11:37:03Z"}
```

### 三条实现纪律

1. **只追加，不改写**。`query_log.jsonl` 是账本，不是缓存。要"修正"就追加一行新的。
2. **零命中照写**。见下一节。
3. **写完自检**：`json.loads` 逐行通过才算写完。别用控制台肉眼看中文（坑 4：文件是好的，显示是坏的，你会去修一个不存在的问题）。

---

## 二、零命中 = 策展缺口（本章最重要的一条）

一个 0 命中记录，同时说明三件事：
- 有人问了一个你的知识库答不上的问题（**需求**）
- 检索式本身可能是错的（**检索问题**，不是知识问题）
- 这个缺口以前没人知道（**可见性**）

所以：

| 做法 | 结果 |
|---|---|
| 不记 | 永远不知道缺什么；复现时只能重查一遍 |
| 只记"查过了" | 分不清"查了没有"和"查了但没命中" |
| 记 `hits:0` + 检索式 + 图 + sha | 缺口可数、可排序、可排期补录 |

**周复盘建议**（10 分钟）：

```bash
python -X utf8 -c "
import json,collections
rows=[json.loads(l) for l in open('query_log.jsonl',encoding='utf-8')]
zero=[r['query'] for r in rows if r['hits']==0]
print('零命中 top10:', collections.Counter(zero).most_common(10))
"
```

对 top10 逐个判：
- **该有而没写** → 进补录清单（带目标实体类型）
- **写法不对**（口语、错别字、跨语言）→ 加别名，不改知识
- **本来就不该有**（范围外）→ 记"范围外"，以后同类查询不重复排查

"查无"不等于"查尽"。一条 `hits:0` 只证明"这一个检索式没命中"，不证明"没有这条知识"。下一步至少再试：同义词、英文名、上游 id（如外部库编号）。**试过的路径要写进 gaps，否则下一个人会重走一遍。**

## 三、快照绑定：任何结论都要能回到一个 sha

| 输出 | 必须带 |
|---|---|
| 单条查询结果 | `snapshot_sha` + `hits` |
| 覆盖率 / 命中率 / 规模数 | `图名 + 快照 sha + 分子分母口径` |
| 报告里引用的事实 | `实体 id + 出处 + source_date + snapshot_sha` |

反例：`"知识库覆盖了 87% 的目标实体"` —— 87% 是什么的占比？哪张图？哪一版？分子分母怎么算？**缺这三个，这个数字不能出现在任何结论里。**

**多图绝不混算。** 两套图各有自己的查询账本和 sha；把 A 图的命中数加到 B 图的覆盖率上，是最常见也最难发现的错误。

---

## 四、检索回归：发布后必跑的双向测试

单向测试只能证明"新东西能搜到"，证明不了"旧东西没坏"。

```bash
# 正向：仍然有效的东西必须还能命中
python -X utf8 tools/kbq.py --root . --q 山谷            # 期望 hits>=1

# 反向：被删/被隔离的东西必须搜不到
python -X utf8 tools/kbq.py --root . --q {{REMOVED_NAME}}  # 期望 hits==0

# 身份：旧 id 必须仍然可解析（改名不应改 id）
python -X utf8 tools/kbq.py --root . --id Book:b-01        # 期望 hits==1
```

三行都过，才叫"检索没退化"。只看第一行，等于只检查了"新增的部分"。

## 五、RAG 装配：给模型的上下文长什么样

最小可用形态就是 `tools/rag_context.py` 的输出：

```
[上下文] 图=demo-books 快照sha=050d0a72…
[实体] Book 山谷与齿轮 (id=Book:b-01, 出处=DEMO_SEED 2026-01-01)
[别名] 山谷
  [d1] 山谷与齿轮 → ABOUT → 人工智能  (出处日期 2026-01-01)
  [d1] 山谷与齿轮 → GENRE_OF → 科幻  (出处日期 2026-01-01)
  [d1] 山谷与齿轮 → WRITTEN_BY → 林砚  (出处日期 2026-01-01)
[边界] 以上是该实体的 1–N 跳邻域；块外未知即说未知，不要补全。
```

### 五条装配规则

1. **每条事实带出处和日期**。模型引用时能落到具体一行，而不是"资料显示"。
2. **深度 1–2 跳**。深了噪声淹没信号；查不清就换更具体的问题，别加深。
3. **必须有边界声明**。没有它，模型用训练记忆填空，你无法区分"图里的"和"它记得的"。
4. **块内按关系类型分组**，别把 40 条边平铺——模型对结构化的分组更不容易串。
5. **给出实体 id**。模型可以回引 `Book:b-01`，下游能再查一次原始记录。

### 引用格式（写进 prompt，也写进报告）

```
[山谷与齿轮] (Book:b-01, 出处 DEMO_SEED 2026-01-01, 快照 050d0a72)
```

四件事齐了，任何人能复核到同一行。缺 `快照` → 无法判断是哪一版；缺 `出处日期` → 无法判断是否过期。

### 结构化检索与向量检索的分工

| | 结构化（本章） | 向量 |
|---|---|---|
| 擅长 | 实体身份、关系、精确命中、可解释 | 模糊语义、跨表述召回 |
| 不擅长 | 同义改写、长句问答 | 实体消歧、"谁是谁"、出处 |

正确顺序：**先用结构化 KG 解决身份和关系，再用向量做候选召回，最后回 KG 校验**。
反过来（先向量后结构）会得到一个"能聊、但说不清来源"的系统——这类系统在需要签字的场合不能用。

## 六、过期知识：标记，不删除

```json
{"id": "Book:b-02", "name": "夜航船说", "invalid_since": "2026-06-01", "note": "作者信息已更正，旧版记录保留"}
```

| 做法 | 后果 |
|---|---|
| 直接删 | 历史结论无法复核；上游不知道曾经有过这条 |
| 标 `invalid_since` + 保留 | 默认查询过滤，显式 `--include-invalid` 可查；审计线完整 |

查询层默认过滤 `invalid_since` 不为空的实体；报告引用过期知识必须写明"该条已于 X 失效"。

## 七、访问方式：查询永远只读

```python
con = sqlite3.connect(f"file:{db_path}?mode=ro", uri=True)
```

查询进程用只读连接打开 `kb.sqlite`。写只发生在 `kb_build.py`（KG）和 `kb_load.py`（索引）。
这样"某人边查边写坏库"这类事故从根上不存在——不是靠自觉，是靠权限。
