# 技能挂载 · {{ROLE_NAME}}

技能（skill）= **把方法论写成可反复执行的文件**，不是提示词堆料。它的价值是：让同一个角色在两次任务里用同一个口径。

## 1. 挂什么

| 技能 | 解决什么 | 什么时候加载 | 不加载会怎样 |
|---|---|---|---|
| `{{SKILL_1}}` | {{WHY_1}} | 任务含 `{{COND_1}}` | 用印象代替标准，输出不可复现 |
| `{{SKILL_2}}` | {{WHY_2}} | 任务含 `{{COND_2}}` | 漏掉必查项 |

- **加载条件要能被判断**：写"当任务里的输入是一组序列"好过"需要时加载"。
- 一个角色挂 **2–4 个**技能为宜。超过 5 个通常是把这个角色拆得不够。

## 2. 技能里必须有哪几段

照这个骨架写，缺一段就会被用歪：

1. **定位条款**：这个技能管什么、不管什么（防止越界使用）
2. **输入制式**：必需字段、字段缺失时怎么办
3. **运行规程**：命令模板 + 退出码含义 + 报错怎么读
4. **判读纪律**：什么算通过、什么算不通过、通过阈值写死
5. **回写义务**：跑完之后要更新哪份台账

## 3. 写法反例

| 反例 | 为什么坏 | 改成 |
|---|---|---|
| `要注意编码问题` | 不可执行 | `Windows PowerShell 5.1 读无 BOM 的 UTF-8 脚本会乱码；.ps1 只用 ASCII 或存 UTF-8 with BOM` |
| `根据经验调整参数` | 无法复核 | `阈值取 X；改阈值必须附上一轮对账数据` |
| `参考相关文献` | 等于没查 | `给出检索式 + 命中数 + 0 命中要写明对应节点` |

## 4. 技能与角色卡的边界

- 角色卡写**责任与边界**；技能写**怎么做**。
- 同一段内容不要两边都写：写两处必然分岔，改一处忘另一处。
- 指向技能时写清"哪个文件哪一节"，别写"参考技能"。
