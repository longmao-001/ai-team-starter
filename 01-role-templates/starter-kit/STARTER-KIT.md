# 基础团队必备八席（STARTER KIT）

八张角色页，**换行业只改占位符**。它们不是"完整团队"，是**一个能交付的最小闭环**。

## 为什么是这八个

一个团队要持续产出，必须同时有人做五件事：**派活、干活、校验、保底座、管杂事**，最后还得有人**交出成品**。八席是这五件事的最小不重叠切分：

| 文件 | 席位 | 一句话职务 | 缺了它会出什么事 | 状态 |
|---|---|---|---|---|
| [`01-manager.md`](01-manager.md) | 管理 | 判型、派工、收口、门控、台账 | 活没人拆、没人收，交付靠"谁想起来谁干" | 待交（作者在写） |
| [`02-it.md`](02-it.md) | IT | 环境能跑、变更可回滚、发布可追溯 | 改坏了退不回去；发布靠手工，无法追溯 | **已交** |
| [`03-admin.md`](03-admin.md) | 行政 | 日程、邮件、文件归档 | 时间与文件靠人脑记，交接即断档 | 待填 |
| [`04-auditor.md`](04-auditor.md) | 审计 | 只认盘上证据、独立复算 | 交付靠自报，错在最后一公里才被发现 | 待填 |
| [`05-kg-steward.md`](05-kg-steward.md) | 知识 | 知识层建设与发布纪律 | 同一问题反复查、结论互相打架 | 待填 |
| [`06-literature.md`](06-literature.md) | 文献 | 读材料、提主张、分级证据 | 判断建立在摘要级信息上，容易被推翻 | 待填 |
| [`07-novelty.md`](07-novelty.md) | 查新 | 查新与矛盾检测、三态措辞 | 重复造轮子；把"没查到"当成"没人做过" | 待填 |
| [`08-report-writer.md`](08-report-writer.md) | 产出 | 把过程做成可交付、可审阅的成品 | **分析得再好也交不出东西**——很多团队就是这样卡住的 | 待填 |

## 上线顺序（每步都能独立见效）

1. **管理** — 先有派工与收口，否则后面的产出无法验收
2. **知识** — 有地方沉淀，否则第二轮要从零开始
3. **文献 / 查新** — 两个一起上：一个负责"读进去"，一个负责"查干净"
4. **审计** — 有人独立复核，前面三步的自报才可信
5. **IT** — 有可回滚的底座，才敢做上面的变更
6. **行政** — 别省：日程与归档断了，前面全白干
7. **产出** — 前六步产出的是**过程**，只有它交**成品**；没有它，团队会一直"分析得很好"却交不出东西

顺序不是价值排序，是**依赖排序**：后一步靠前一步的输出活着。

## 首周最小动作（八个席位各做一件事）

| 席位 | 本周必须产出 |
|---|---|
| 管理 | 一张真实派工单 + 一次收口回执 |
| 知识 | 一个真实问题能从"问"走到"带来源的回答" |
| 文献 | 一份材料的主张清单（每条带证据级别） |
| 查新 | 一条检索记录：检索式、命中数、0 命中对应哪个节点 |
| 审计 | 对上面任一份交付做一次独立复算，给 PASS / FAIL |
| IT | 一次变更单（含旧 sha → 新 sha 与回滚步骤） |
| 行政 | 一份可交接的文件清单（谁、什么时候、放哪） |
| 产出 | 一份完整成品：封面、结论、依据、附录 |

## 共用的底线（八页都只写指针）

- 报数带口径：数字 + 口径 + 范围 + 快照时点或哈希
- 负结论回显依据：查了什么、0 命中对应哪一条
- 不编造：缺数据写"缺"
- 状态断言前先核实际状态，不照台账念
- 发布门只跑现成脚本，覆盖数为 0 判 FAIL

## 怎么用

1. 把八个文件复制到你的仓库，只改 `{{ORG}}`、`{{DOMAIN}}`、`{{DELIVERABLE}}`、`{{RUN_PATH}}`
2. 按上面的顺序一个一个上，每上一个就让它产出一件真东西
3. 每个席位每周至少一次真实交付，否则它只是聊天窗口

## 这不是终点

八席跑顺之后再加：领域专家（给判断、不给执行）、执行型 agent（固定输入输出）、制片人型管理（管多条产线）。
**加之前先回答"它补哪个具体缺口"，答不上就别加**——每加一个角色，收口成本都会上升。
