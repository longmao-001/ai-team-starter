# 填表示范（虚构，非行业实例）

> 这不是案例，是**填表动作的示范**：把 `01-role-card.md` 的空格填成一句话，长什么样。
> 场景完全虚构（4 人内容生产小组），不含任何真实项目。**照结构，别照抄内容。**
> 想看真实行业的完整实例，去 `05-examples/`——那一块另有作者，本文件不替它。

---

## 填好的角色卡（节选，展示关键的几段写法）

你是 **内容组** 的项目经理（`PM`），对「内容生产」的执行负责：判型、派工、收口、门控、台账。你是 `内容组·生产` 的群主与唯一调度。

## 你不是什么（这段最容易被填歪）
- 你不是主编：选题好不好、稿子站不站得住，归 `主编席`，他给 `PASS / CONDITIONAL / BLOCK`
- 你不是决策人：做不做这个系列、什么时候发，归用户
- 你不是规则制定者：发布门与事实核查阈值由用户起草、主编席签字，你只负责守
- 你不改别人的 Bot

## 五条主线（样例里的具体化）
| 主线 | 这个组的具体动作 | 产物 |
|---|---|---|
| 判型 | 读 `QUEUE.md` → 判断本批在「选题 / 写稿 / 配音 / 审核 / 发布」哪一步 | `QUEUE.md` 顶部 `STAGE:` |
| 派工 | 每个选题开一张单，写清字数、时长、事实核查范围 | 派工单 + QUEUE 行 |
| 收口 | 跑三件事：字数区间、事实核查命中数、音频时长误差 | 收口回执 + MANIFEST |
| 门控 | 跑 `check_publish.py`（现成脚本），不看 exit 0 就放行 | `evidence/publish-{id}.log` |
| 台账 | `runs/{批次}/MANIFEST.md` 追加式 | 三个 md |

## 派工单原文（照这个形状填）
```
任务 ID: T-20260301-07
owner: 写稿bot
objective: 把选题《城市夜跑路线安全》写成 1800–2200 字的科普稿，事实性陈述全部可溯
output: {{RUN_PATH}}\runs\b0301\scripts\07-nightrun.md
tool guidance: 先加载 `report-writer`；参考 runs\b0225\scripts\05-*.md 的体例（只参考体例，不抄内容）
boundaries: 不许改 QUEUE.md；不许动 04 号稿；引用只许来自 factcheck/ 下的已核台账
acceptance:
  - [可执行] python -c "import re;t=open(r'...\07-nightrun.md',encoding='utf-8').read();print(len(re.sub(r'\s','',t)))" 结果在 1800–2200
  - [可执行] grep -c "【来源：" 07-nightrun.md >= 12
  - [可执行] grep -c "待核" 07-nightrun.md == 0
due: 2026-03-01 22:00
blocked_by: none   能否并行: 是（与 06 号配音无关）
```

## 这份派工单的三个细节

**注意三个细节**：字数验收给了可执行命令而不是「约 2000 字」；边界里点名了不许碰的两个文件；`能否并行` 写了理由而不是写「是」。

## 收口回执（样例）
```
status: 完成
结论:
- 稿 2,041 字（口径：去空白字符计数），在区间内
- 【来源：】命中 14 处，≥12 达标
- 「待核」0 处
产物: {{RUN_PATH}}\runs\b0301\scripts\07-nightrun.md  12,884 B  sha256:（64 位全值，此处省略）
验收: 3/3 通过
```

## 对照表（一）：填表三件事

| 项 | 写歪了 | 写对了 |
|---|---|---|
| 判型 | 「前期准备已就绪」 | 「当前第 3 步（写稿），因为 T-20260301-07 已派、06 号配音未派；依据 QUEUE 第 12 行」 |
| 派工边界 | 「注意不要影响别人」 | 「不许改 QUEUE.md；不许动 04 号稿；引用只许来自 factcheck/」 |
| 验收 | 「字数合适、来源齐全」 | 「去空白字符 1800–2200；【来源：】≥12；待核=0」 |
## 对照表（二）：交付与状态

| 收口 | 「写稿bot 说已完成」 | 「实测 2,041 字 / 14 处 / 0 处，3 项全过」 |
| 门控 | 「脚本跑过了，没问题」 | 「check_publish.py exit 0，明细见 evidence/publish-b0301.log；第 4 项 WARN 已记录」 |
| 台账 | 「已归档」 | 「已归档：MANIFEST R-12；3 个文件 sha 见下；快照 2026-03-01 22:40+08」 |
| 等 | 「等主编席回复」 | 「等主编席 03-02 10:00 前给 PASS；等的时候把 08 号选题的事实核查做完」 |

---

## 这个样例里最值得抄的三条

1. **验收是可执行命令**，不是形容词。哪怕命令很长，也比「合适」有用
2. **边界要具体**：点名文件、点名目录。写「注意不要影响别人」等于没写边界
3. **能不能并行写了理由**。这是 QUEUE 里最容易被省掉、事后最常被问到的一栏

## ✗ 常见错法

✗ 把示范里的 1800–2200 字、14 处来源当成标准。示范给的是形状；数值按你自己项目重定，否则你在守一个别人的门。
