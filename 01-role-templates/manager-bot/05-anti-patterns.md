# 反例：管理 bot 写歪了长什么样

> 12 种真实退化形态。写完角色卡对着扫一遍，命中两条以上就回去改——这些坑不是理论，是踩出来的。

## 形态层（角色卡本身写错）

### 1. 只有形容词，没有动作
```
你是一位经验丰富的资深项目经理，擅长统筹协调，具备优秀的沟通能力……
```

**为什么错**：agent 无法执行「经验丰富」。全段读完没有任何一个可以做的动作。
**改法**：每条能力改写成「动作 + 产物 + 判据」。判据一问：**这条能验收吗？**

### 2. 「负责一切协调」
**为什么错**：无边界的角色会主动做三件不该做的事——替专家下结论、替用户做决定、替执行方改文件。
**改法**：写死「你不是什么」一节，每条「不是」后面必须跟「归谁」。写不出归谁，说明团队分工本身还没定。

### 3. 没有升级点
**为什么错**：遇到超出权限的事，它的选择只有两个——自己编，或者停下来问你。前者更常见，也更贵。
**改法**：写明四类才上报，并加一句「四类以外自己定，不要反问要不要继续」。不定这条，它会每三步问你一次。

### 4. instructions 写成 5000 字长文
**为什么错**：关键条款被自己的字数淹没；改一处要动整个 instructions，容易改出新矛盾。
**改法**：instructions 只留「你是谁 / 你不做什么 / 五条主线 / 升级点」；细则进 skill（见 `03-skill-bindings.md`）。

### 5. 让管理 bot 顺便打分/裁决
**为什么错**：判据和执行在同一个脑子里，会互相迁就——执行方累了就放松验收，判据严了就不敢派活。这是最隐蔽的一种退化。
**改法**：打分、裁结论、改正文明确划给专家席；管理 bot 只负责「验收串过没过」。

## 运行层（角色卡对了，跑起来还是歪）

### 6. 派工不写验收，收口只能信自报
**现象**：「已完成」「已处理，无新动作」。
**为什么错**：没有验收串，你唯一的信息源就是执行方的自我评价。它不知道自己漏了什么，你也看不出它漏了什么。
**改法**：派工单里每条验收都能被第三方复制执行。

### 7. 派工点对点，别人看不到在途
**现象**：同一个任务被两个 bot 各做一遍；或者两个人都在等对方。
**为什么错**：点对点派工没有第三双眼睛，重复和死锁都发现不了。
**改法**：派工进群 + 一张在途表（谁在跑、跑到哪、卡在哪）。点对点只留给背靠背盲评和独立判断。

### 8. 台账用聊天记录代替
**现象**：换台电脑、开个新会话，问「现在到哪一步」答不上来。
**为什么错**：会话是隔离的，聊天记录不是台账。
**改法**：三件落盘——`QUEUE.md`（在途）、`MANIFEST.md`（追加式交付账）、`PROVENANCE.md`（产物现值）。

### 9. 台账里写「已完成」
**现象**：QUEUE 上一堆 RUN，其中一半其实早做完了没标；或者标了 DONE 但盘上没产物。
**为什么错**：「已完成」既不可核也不可重算。台账状态不等于实况。
**改法**：DONE 行必须带三样——产物绝对路径、sha、验收命中数。「全清 / 无在途 / 已归档」这类断言一律带快照 sha + 时点。

### 10. 没有 WIP 上限
**现象**：在途十条，每条都是半成品，没有一条能交。
**为什么错**：并行度不是越高越好。半成品和半改文件是最危险的中间态。
**改法**：在途单 ≤ 3（研发/内容都适用）。超了先收口，不派新单。

### 11. 用「等」结束一轮
**现象**：「等主编席给结论。」——然后全队空转。
**为什么错**：一个环节堵住，不等于所有工序都得停。
**改法**：说「等」必须同时说三件——在等什么、等的时候在做什么、什么时候重判；并把「不依赖该环节的工序」全部派出。

### 12. 让执行方自己去核自己的交付
**现象**：交稿方说「已自查，无问题」。
**为什么错**：自产自检等于没检，人会看不见自己的盲区。
**改法**：验收人必须是下游或独立方，只核数，不核内容偏好。
