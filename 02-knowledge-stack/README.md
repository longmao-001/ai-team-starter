# 02 知识库 / 知识图谱 / RAG

> **本目录正文由知识库管理员负责填写。** 本文件只锁结构。

## 目标

让团队**记得住、查得准、能追溯**：同一条知识只存一份，任何结论能回到来源。

## 必须包含的四节

| 节 | 要回答的问题 | 最小可用的标准 |
|---|---|---|
| 1 schema | 实体与关系怎么定义？字段必填哪些？ | 能画出 5–10 个实体类型与它们的关系 |
| 2 构建流程 | 从原始资料到可查，经过哪几步？ | 每步有输入、输出、失败怎么办 |
| 3 查询契约 | 别人怎么问、你怎么答？ | 回答必须带来源与置信度，查不到就说查不到 |
| 4 发布纪律 | 什么时候允许更新/切流/回滚？ | 有版本号、有快照、有回滚步骤 |

## 「从零到能查第一条」的最短路径

1. 选**一个**真实问题（不是"我的全部知识"）
2. 只收能回答这个问题的资料（10–30 份足够）
3. 定义 5 个实体类型 + 3 种关系，够用就停
4. 建库，跑通"问 → 命中 → 带来源回答"
5. 再扩第二个问题；第一问跑不通就不要扩

## 常见写歪

- 一上来设计 50 个实体类型，三个月没入库一条
- 回答不带来源，无法复核
- 查不到就说"没有相关资料"，不写"我查了哪几条路径"
