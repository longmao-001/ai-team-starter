# Day 1：从空文件夹到第一个 bot 跑起来（步骤 0–3）

时间盒：**半天到一天**。四步做完，你会有一个按你真事答过的 bot，以及两个必须留下的文件。
没勾的步骤不要进入下一步——跳一步的代价不是慢一天，是后面每一步都在补这一步的窟窿。

## 步骤 0 想清楚交付什么（30 min）

写一页 `SCOPE.md`，回答三问：

- [ ] **输入从哪来**：一句话说清起点（谁给、什么格式、多久一次）
- [ ] **输出到哪**：产物落在哪个目录、叫什么名字
- [ ] **谁验收**：一个具体的角色名（「我自己」也算，但要写成「我，按第 2 条的判据」）

不满足就别往下走：验收人写不出具体角色，只写得出「团队」。
卡住时：把验收人想成「出问题时第一个被问的人」。想不出这个人，说明这件事现在还不该做。

## 步骤 1 定工作目录（20 min）

- [ ] 定一个**绝对路径**当工作目录，写进 `ENV.md`
- [ ] 在里面新建一个文件，再读回来，内容一致
- [ ] 确认路径里的中文与空格不会出问题（有就换个纯英文路径）

不满足就别往下走：`pwd` 输出的路径与 `ENV.md` 里写的不是同一个。
卡住时：路径里有空格时，命令要整体加引号；路径里有中文时，先在命令行里 `cd` 一次看会不会乱码。

## 步骤 2 跑通环境（60 min）

- [ ] 装好运行环境（模型客户端 / Agent 平台 / 解释器）
- [ ] 跑通一条最小命令，例如读一个文件输出一句话
- [ ] 把**命令原文、输出、版本号**抄进 `ENV.md`

不满足就别往下走：只有「我记得装过」，没有 exit code 与输出。
卡住时：Windows 上 `.ps1` 存成无 BOM 的 UTF-8，中文会乱码、引号失配、脚本静默不执行——要么脚本只用 ASCII，要么存成 UTF-8 with BOM。

## 步骤 3 建第一个 bot（60 min）

按 [`01-role-templates/manager-bot/01-role-card.md`](../01-role-templates/manager-bot/01-role-card.md) 填一份角色卡，五段齐全：

- [ ] 身份：它是谁、对什么负责
- [ ] **你不是什么**：每条「不是」后面必须跟「归谁」
- [ ] 五条主线：判型 / 派工 / 收口 / 门控 / 台账
- [ ] 铁律：≤6 条，每条能验收
- [ ] 升级点：只有哪几类才需要问你

不满足就别往下走：你能一句话说出它**不做什么**；说不出，或者「你不是什么」段写成「它什么都能干」，回上一步。
卡住时：第一个 bot 建**管理型**的（只判型、派工、收口），不要先建执行型——执行型没有可验收的输入输出定义时，写出来的角色卡一定是空的。

## 步骤 3.5 拿一件真事试一次（30 min）

- [ ] 给它一件**今天真要用**的小事（不是「介绍一下你自己」）
- [ ] 看它回答里有没有：它准备怎么判型、缺什么信息、要谁来验收
- [ ] 把它的偏差写回角色卡（至少一条边界）

不满足就别往下走：它答得像客服（「我很乐意帮您」），或者什么都没问就开始了。
卡住时：把「你不是什么」段再收紧一条，比在别处加规则有用。

## 常见写歪

- 跳过步骤 0 直接装环境 → 三天后说不清这个团队在交付什么
- 步骤 1 用相对路径 → 换一次目录，所有产物散落
- 步骤 2 记录「已安装」而不是命令与版本 → 出问题时要重新摸一遍
- 步骤 3 三个角色一次建完 → 每个都只有半条命

## ✗ 常见错法

✗ 把「做完的标志」写成「环境已就绪」「角色已建好」这类状态词。标志必须是可指的东西：一个有内容的文件、一条 exit 0 的命令、一句能复述的边界。
