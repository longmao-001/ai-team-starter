# 实例 · 某短剧项目（脱敏）

> 状态：已填。负责：制片人。骨架（判型 → 派工五要素 → 门控 → 台账）与科研、育种两个实例完全相同，只换行业数据。

## 1. 判型

拿到「把一部小说改成短剧」的请求，先答三问再派工：

| 判型问题 | 答案 | 结论 |
|---|---|---|
| 有剧集属性（多集 / 连续）吗 | 是，短剧按集推进 | 剧本驱动通道 |
| 主产物形态 | 剧本（靠戏剧动作推进） | 不是口播稿、不是音乐 |
| 走哪条产线 | 已有小说 → 改编 | 改编线：先出小说，再改剧本 |

判型结果：剧本驱动通道、档位 M（默认 6–7 人，只上编剧席，其余待命）。改编三原则先立：提纯核心冲突、内心戏外化成可拍动作、章节转集结构；小说对白不原样搬进剧本。

## 2. 派工五要素

| 项 | 内容 |
|---|---|
| 输入 | 小说的「指控靶子 / 人物身份 / 证据来源 / 在场关系」四件地基；四件缺一判改编损伤、不进盲评 |
| 输出形态 | 先派小说作者出 1–3 万字稿 + 改编卡，再派编剧出分集剧本；产物落 `{{RUN_PATH}}/` |
| 验收串 | 机器门 exit 0 + 盲评过 + 数字 / 金额 / 时间线对账（见第 3 节） |
| 时限 | 同一体例只上一个编剧席，其余待命；在途 ≤4 |
| 升级路径 | 连续两轮无实质进展换角色 / 换路线并上报；盲评 BLOCK 不单方推翻 |

派工单上 objective / output / tool guidance / boundaries / acceptance / due 六栏必须写全，缺一栏不算派出。改编线铁律：tool guidance 里必须点名「改编地基四件」，四件缺一判改编损伤、不进盲评。

## 3. 门控

顺序不能乱：两道机器门 → 一道盲评 → 一道对账。

| 门 | 判据 | 不过怎么办 |
|---|---|---|
| 机器门 | 小说 `check_story`、剧本 `check_shortdrama` 都 exit 0；exit 2 按 FAIL | 打回改，最多 2 轮 |
| 盲评 | 品评员 / 观众代言人 / 审片人背靠背打分 → 交齐后辩分歧 → 制片人裁决合并改稿单 | BLOCK 不单方推翻，报 Chief |
| 对账 | 数字 / 金额 / 时间线逐条对 | 源头锁版才开写 |

```text
# 运行目录：{{RUN_PATH}}
python check_story.py     story.md   # exit 0 = 小说过
python check_shortdrama.py ep1.md    # exit 0 = 剧本过
```

对账是机器门和盲评都抓不到的字面错，收口必须单独做。真实踩过：

| 现象 | 原因 | 改法 |
|---|---|---|
| 小说写「追回 X万」，剧本写成另一个数，返 3 轮 | 源头金额没锁版就开写 | 源头锁版才开写，收口单独对一遍金额 |

## 4. 台账

一轮结束时，在途表长这样（「卡在哪」必填，写 none 也要写）：

| 任务ID | owner | 状态 | 跑到哪 | 卡在哪 | due |
|---|---|---|---|---|---|
| T-1108-01 | 小说作者 | DONE | 出稿 + 改编卡 | none | 11-08 12:00 |
| T-1108-02 | 编剧 | RUN | 改第 3 集 | 等改编卡四件齐 | 11-08 22:00 |
| T-1108-03 | 品评员 | WAIT | 未开始 | 等剧本过机器门 | 11-09 10:00 |

收口后同轮做三件事：QUEUE 行改 DONE 指回产物、MANIFEST 追加交付行、新暴露的坑写进坑注册表。

## 5. 占位符对照表

| 占位符 | 替换了原稿哪类信息 | 出现次数（全文） |
|---|---|---|
| `某短剧项目（脱敏）` | 真实项目名 / 剧名 | 2 |
| `X万` | 真实金额（制作费） | 2 |
| `{{RUN_PATH}}` | 盘符 / 内网路径 | 3 |

> 计数口径：全文出现次数（含标题 1 次、本表自身 1 次），与扫描器 grep 全文的口径一致。

## 常见写歪

影视业最容易写歪的一点：把制作流程写成作品宣传。「我们的剧本多精彩」不是教程。读者要的是「判型问哪三问、派工单六栏写什么、门控跑哪个脚本、不过怎么办」——剧情本身一行都别展开。
