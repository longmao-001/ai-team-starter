# 坑注册表

> 每条都是「现象 → 原因 → 改法」。**能让人少踩一次的才叫教程**；「要注意细节」不算。
> 用法：开工前扫一遍；踩到新坑，当场追加一条。

## 台账类

### P1 台账里一堆「在做」，一半早做完了
**现象**：QUEUE 上 RUN 行很多，问起来大半其实已交。
**原因**：状态只在开工时写，收口时不回写。
**改法**：收口同时改状态。日巡时对着 mtime 核一次 RUN 行。

### P2 报「已完成」但盘上没东西
**现象**：回执说交了，按路径打开是空的或旧的。
**原因**：没有验收串，交付靠口头。
**改法**：派工单必须含可执行验收；收口时逐条跑，命中数写出来。

### P3 两个人并行写同一份台账，丢了一次
**现象**：MANIFEST 少了几行，或者序号重复。
**原因**：没有「单一写者」约定。
**改法**：每个台账文件指定唯一写者；其他人只读，需要写就提请求。写前先 `_tmp` 再原子替换，不要就地追加。

## 报数类

### P4 报了哈希却对不上账
**现象**：两个人报的哈希值不同，被当成「文件被改过」。
**原因**：没写算法名与位数。`sha256:` 前 16 位与 `md5:` 全值是两个不同的值，但各自都对。
**改法**：报哈希必须带算法名 + 位数 + 是否全值；对不上时先核口径（算法/位宽），再谈冲突。

### P5 「0 条」到底是查了没有
**现象**：报「未受影响 0 条」，事后发现有影响。
**原因**：检索路径不存在，工具静默返回 0。
**改法**：负结论必须带路径存在性检查与检索式。区分「查了没命中」与「没查」。

### P6 行数对不上
**现象**：一份文件，38 行 / 26 行 / 39 行三个数都被报过。
**原因**：LF 计数 / 非空行 / split 含尾空段，三个口径都真实。
**改法**：报行数写明口径。

## 批量操作类

### P7 批量替换把 A 的内容替换进了 B
**现象**：清单文件里，第 1 条的三行变成了第 4 条的内容。
**原因**：用宽松正则做整块替换，命中了第一个同结构条目。
**改法**：用唯一整串精确替换；改后逐条核徽标与计数。

### P8 大小写替换产生重复前缀
**现象**：出现了「van Van Nguyen」这类双前缀。
**原因**：工具默认不区分大小写，替换后的文本又被下游规则再命中一次。
**改法**：显式指定区分大小写；替换后立即搜残留。

### P9 批量改前没测命中数，改完才发现少改
**现象**：说改了 69 处，实际只有 6–8 处。
**原因**：某些 API 的查找循环会在同一个范围上重复计数。
**改法**：改前先实测命中数并记下；能用一次性替换就不要用循环。异常立即回滚。

## 环境类

### P10 脚本读出乱码 / 行数少了一半
**现象**：某 shell 环境读无 BOM 的 UTF-8 脚本出现乱码；行数统计比实际少。
**原因**：读取层的默认编码与文件实际编码不一致。
**改法**：读取时显式指定编码（如 `encoding='utf-8'`）；关键计数用脚本重算，不用文本工具目测。

### P11 用户在编辑文件时被我们关掉了
**现象**：文档被关，用户未保存的修改丢失。
**原因**：为了改内容先关闭了文档。
**改法**：能在应用内原地改的就原地改，不关窗口；确需关闭时先确认已保存、先备份、改完立刻重开并说明原因。

## 协作类

### P12 派工点对点，重复劳动 / 互相等待
**现象**：同一任务被做两遍，或两个人都在等对方。
**原因**：没有第三双眼睛看见在途。
**改法**：派工进群 + 在途表。点对点只留给背靠背盲评。

### P13 有 bot 闲着，同时有 TODO 挂了一整天
**现象**：进度不动，问起来在「等指示」。
**原因**：派工看的是「谁问了」，不是「谁空了」。
**改法**：每轮开工先看谁空闲，空闲 + 有 TODO = 违规。

### P14 「等专家」等成了一周
**现象**：一个门挂着，全队停摆。
**原因**：把门当成了整体暂停键。
**改法**：门挂着时当场列出「不依赖该门的工序」并全部派出。

## 交付类

### P15 半改的文件被当成成品
**现象**：文件改了 6 处中的 4 处，下游按新口径引用。
**原因**：收口时只看「改了没有」，没看「改齐没有」。
**改法**：半改不收，列出缺项；要退就退整份再讨论。

### P16 交付件格式要求被漏掉
**现象**：用户提过「要修订模式」，这一轮改成普通文本。
**原因**：格式要求只在被点名那轮复核了。
**改法**：用户提过的格式要求列成固定清单，每轮在产物上复核一遍。

## 追加坑的模板

```
### P{{n}} {{一句话现象}}
**现象**：{{看到什么}}
**原因**：{{为什么会这样，不要写"手滑"}}
**改法**：{{改规则/改脚本/改模板，不要写"下次注意"}}
```

## ✗ 常见错法

✗ 只读不追加。同一个坑踩第三次，因为没人把新坑记进这张表。
