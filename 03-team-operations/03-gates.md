# 阶段门（Gates）

> 门的作用是**在花更多成本之前，先确认前一段真的成立**。门写歪了有两种后果：门太松，等于没有；门太严，全队陪它停摆。

## 门的三个要素

| 要素 | 要求 | 反例 |
|---|---|---|
| **判据** | 可执行的检查（脚本 / 计数 / 比对），不靠人眼看 | 「方案是否合理」 |
| **签字人** | 一个人，不是「大家」 | 「团队确认」 |
| **预注册** | 开跑前就写下的预期值（预期计数、预期 sha） | 事后根据结果倒推标准 |

**预注册为什么重要**：门在事后才定，就等于让结果解释标准。事后补的文件只能标「事后登记·非预注册」，不倒签。

## 门只冻结论，不冻工序

这是最容易被误操作的一条。门挂着的时候，团队最常见的反应是「整体暂停，等结论」——**这是让全队陪一个门停摆**。

正确动作（同一轮做完）：

1. 列出「**不依赖该门**的工序」清单
2. 把清单里的工序**全部派出**
3. 把卡住的工序写进 QUEUE 的 `blocked_by`

**判据**：门挂着超过一轮而队列里没有新增任务，就是违规。有 bot 闲着 + 有 TODO，这一轮不算完。

## 门的运行纪律

- **只跑现成脚本**：不改阈值、不放宽、不为了过而改脚本
- **跳过 ≠ 通过**：没跑的项一律记「未涉及」，不记 PASS
- **`exit 2` 不等于通过**：任何非 0 退出码都要读明细
- **FAIL 先分类**：是产物真的不达标，还是匹配规则写错了（大小写、只写不读的旁路文件、路径不存在静默返回 0）。核实后再判，不照抄退出码
- **缺票只能出临时版**：评审类门涉及多人签字时，缺席只能出「临时版·未生效」，标题带词、首行写明缺哪席，**禁写定级**。缺票席不参评须本人明说，不能由主持席推定

## 门控输出怎么存

```
evidence/
  {{门编号}}-{{日期}}.log     # 脚本原始输出（含 exit code）
```

**为什么存**：门的结论将来会被引用。没有原始输出，「当时过了」就是一句无法追溯的口头保证。

## 一个门该不该设：三问

1. **这个门挡住的失败，代价有多大？** 代价小于跑门成本的门，不设
2. **判据能不能写成脚本？** 写不成脚本的门，先降级成人审清单，并标注「主观」
3. **过了这个门，下一段会不会重做？** 会重做的门必须设——返工是最贵的失败

## 门的常见退化

| 现象 | 说明 |
|---|---|
| 门永远「条件通过」 | 等于没门。要么改判据，要么撤门 |
| 门规越来越细 | 说明在执行层反复犯同一类错，该改的是流程不是门 |
| 门由执行方自己签 | 自产自检。签字人必须是下游或独立方 |
| 门的历史结论没有原始输出 | 追溯不了，等于传言 |

## ✗ 常见错法

✗ 门挂着就整体暂停，等专家。全队陪一个门停摆，而不依赖它的工序一条也没派。
