# 04 从零搭队

两天能跑起来的最小路径。**每一步都有"做完的标志"**——没有标志的步骤等于没做。

- [Day 1：从空电脑到三个 bot 能对话](DAY1.md)
- [Week 1：从能对话到能交付](WEEK1-CHECKLIST.md)

## 为什么是两天

- 第一天解决**能跑**：环境、模型、三个角色、一次真实任务。
- 一周内解决**跑得住**：派工单、验收串、台账、备份。

> 顺序不能反。先建制度再跑任务的团队，制度会为空转；先跑任务再建制度，制度是从痛点长出来的。

## 先明确三件事（30 分钟）

1. **你要它干什么？** 写一个"这周就要用"的具体任务，不要写"提升效率"。
2. **谁验收？** 每个产出必须有一个署名的验收人，不能是"团队"。
3. **数据在哪？** 输入从哪来、输出放哪、什么不许外发。

三件事写在一页纸上，贴在项目根目录 `SCOPE.md`。**写不出第 2 条就别往下走**——没人验收的产出，最终一定是烂的。

## 常见写歪

- 第一天就设计完整制度（建了 20 个模板，一个任务没跑）
- 同时上 6 个角色（每个都只有半条命）
- 没有验收人，产出靠"感觉还行"
