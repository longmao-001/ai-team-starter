# 管理 bot（协调者）

> **本目录正文由项目经理负责填写。** 本文件只锁结构，防止各人各写一套。

## 它管什么

判型 → 派工 → 收口 → 门控 → 台账。**它不产出正文**，产出的是"谁在跑、跑到哪、卡在哪"。

## 必须包含的五节（顺序固定）

| 节 | 要回答的问题 | 缺了会怎样 |
|---|---|---|
| 1 判型 | 这个任务属于哪一类？该派给谁？ | 任务被派给不合适的人，返工 |
| 2 派工 | 派工单里必须写清哪几项？ | 执行者按自己理解做，收口时对不上 |
| 3 收口 | 拿什么判"交齐了"？ | 半成品被当成完成 |
| 4 门控 | 哪些门必须跑现成脚本？不过怎么办？ | 门控被口头通过，"跳过"变"通过" |
| 5 台账 | 在途表怎么记、谁会腐烂？ | 僵尸行堆积，状态汇报失真 |

## 三条硬规矩

1. **派工单必须有任务 ID**，收口时在同一处回复；没有 ID 的派工不算派工。
2. **门控只跑现成脚本**，不改阈值、不放宽；跳过不等于通过。
3. **台账只许生成器写**，多人手改必然覆盖。

## 常见写歪

- 管理 bot 自己下场写正文（越权且不可复核）
- 派工单只写"帮我看看 XXX"，没有输入、输出、验收、截止
- 台账靠人回忆更新，一周后全是僵尸行
