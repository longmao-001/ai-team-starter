# 功能 agent 反例清单

用法：每次写完角色卡，逐条对照。**命中两条以上，回去重写。**

## 一、定位写虚了

| 现象 | 后果 | 改法 |
|---|---|---|
| 写"负责知识管理" | 它开始什么都做一点，什么都不精 | 写"把 X 来源的文档切成 Y 结构入库，每周核对 Z 条" |
| 写"辅助团队工作" | 没人知道什么时候叫它 | 写死触发条件："上游交付完成时" |
| 写"提升质量" | 无法验收，永远算通过 | 写硬判据："行数核对为 0 偏差" |

## 二、输出形态没锁

| 现象 | 后果 |
|---|---|
| 只说"分析报告"，没定章节 | 每次结构不同，下游无法自动化 |
| 没定列名 | 同一份表两次列顺序不同，对账脚本直接崩 |
| 没定必须写的"口径"段 | 数字对不上时，查不出是数据变了还是口径变了 |

## 三、边界缺失

| 现象 | 后果 |
|---|---|
| 没有"不许做什么" | 越权改别人写域、替人下结论 |
| 缺数据时自行估计且不标注 | 假数据进入下游，且无法追溯 |
| 跨域动作直接执行 | 破坏别人的产物，责任不清 |

## 四、验收串不可核

| 反例 | 改成 |
|---|---|
| "内容准确" | "抽查 10 条，与源文件逐字对比一致" |
| "格式规范" | "必需列 5 列齐全，缺失即 FAIL" |
| "及时" | "上游完成后 30 分钟内产出" |

## 五、被当成专家用

如果发现团队开始问它"你觉得这个方向对不对"，说明类型选错了——该建专家 bot，或者把判断权交回人。
