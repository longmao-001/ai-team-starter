# Week 1：从能对话到能交付

Day 1 之后，一周内要补上"跑得住"的四件事。**每件都有可核的完成标志。**

## 1. 派工单（周一）

- [ ] 固定字段：任务 ID / 输入 / 输出形态 / 验收串 / 截止 / 升级路径
- [ ] 没有任务 ID 的派工视为无效派工
- [ ] 收口在同一处回复，不许私聊汇报

**完成标志**：本周所有派工都能在台账里按 ID 找到。

## 2. 验收串（周二）

- [ ] 每类交付写一条**机器可核**的判据（行数、列名、哈希、门控输出）
- [ ] 判据里禁止出现"质量高""内容详实"
- [ ] 不通过时的处理写死：只改判据指出的那一处

**完成标志**：随便抽一份交付，别人能照着判据 5 分钟内判出通过与否。

## 3. 台账（周三–周四）

- [ ] 在途表：谁在跑、跑到哪、卡在哪
- [ ] 已收表：任务 ID、交付物路径、哈希、验收人、日期
- [ ] 僵尸行规则：超过 X 小时无更新的行，必须由管理 bot 收口或关闭

**完成标志**：状态汇报前先核实际状态，不照台账念。

## 4. 备份与恢复（周五）

- [ ] 列出**必须备份**的东西（产物、配置、知识库）
- [ ] 备份频率与保留份数写死
- [ ] **做一次恢复演练**：从备份还原到空目录，能用
- [ ] 记下恢复耗时

**完成标志**：演练成功，且你知道"从零恢复到能用"要多久。

> 只做备份不演练，等于不知道自己有没有备份。

## 周末复盘（30 min）

三个问题，答案写进 `WEEK1-RETRO.md`：

1. 这周哪次返工最贵？**根因**是哪条缺失的规则？
2. 哪条纪律被跳过了一次？为什么能跳过？**补哪条堵住它**？
3. 下周要加的**唯一**一个角色或工具是什么？（只加一个）

## 常见写歪

- 四项全做但都没写死 → 下周全部失效
- 恢复演练跳过，理由是"备份日志显示成功" → 日志不等于能恢复
- 复盘写成流水账，没有"补哪条规则"
